# Архитектура 219 · key-checkout-log

## Схема

```
Браузер (React SPA: #keys, #active, #overdue, #history, #staff)
   │  fetch /api/*, cookie kl_session (HttpOnly, SameSite=Lax)
   ▼
FastAPI (uvicorn, один процесс)
   ├─ web.py      вход, сессии, роли, /api/health, /api/demo/*
   ├─ main.py     маршруты, роли duty/admin, CSV-ответ
   └─ service.py  каталог, выдача и возврат, просрочка при чтении, история, экспорт
   ▼
SQLite (WAL, foreign_keys=ON), файл /data/key-log.sqlite3 в томе keys-data
```

## Модель данных

| Таблица | Назначение | Ключевые ограничения |
|---|---|---|
| `users`, `sessions` | дежурные и администраторы | `role IN ('duty','admin')` |
| `keys` | ключ: метка на бирке, помещение, заметка, ключ поиска | уникальная `label` |
| `key_copies` | физический экземпляр: номер в пределах ключа, отметка о списании | `UNIQUE(key_id, copy_no)` |
| `staff` | сотрудники, которым выдают ключи | — |
| `loans` | выдача: экземпляр, сотрудник, кто выдал, когда, плановый срок, фактический возврат, кто принял | **`loans_one_active_per_copy ON loans(copy_id) WHERE returned_at IS NULL`** |
| `events` | журнал: выдача, возврат, ключ, экземпляр, списание, сотрудник | `kind` из фиксированного списка |

Доступность и просрочка не хранятся. Экземпляр доступен, если не списан и у него нет выдачи с `returned_at IS NULL`. Выдача просрочена, если она активна и `now() > due_at` (строго).

## API

| Метод и путь | Роль | Что делает |
|---|---|---|
| `GET /api/keys?q&available&limit&offset&brief` | дежурный | страница ключей с экземплярами и активными выдачами; `brief` — только метки для фильтра |
| `POST /api/keys`, `POST /api/keys/{id}/copies`, `PATCH /api/copies/{id}` | администратор | ключ с экземплярами, новый экземпляр, списание (409, если выдан) |
| `GET /api/staff`, `POST /api/staff` | дежурный / администратор | сотрудники |
| `POST /api/key-loans {copy_id, staff_id, due_at}` | дежурный | 201 — выдача; 200 — тот же экземпляр уже у этого сотрудника; 409 `copy_taken` с текущей выдачей в `loan`, 409 `copy_retired` |
| `POST /api/key-loans/{id}/return` | дежурный | возврат; повтор — `changed=false`, время закрытия прежнее |
| `GET /api/key-loans?status=active|overdue|returned|all` | дежурный | выдачи с признаком `overdue` и серверным `now` |
| `GET /api/events?key_id&kind&from&to&limit&offset`, `GET /api/events.csv` | дежурный | история и CSV с теми же фильтрами |

## Выдача и возврат

```
POST /api/key-loans
  BEGIN IMMEDIATE
    экземпляр списан?                 → 409 copy_retired
    активная выдача этому сотруднику?  → 200, та же выдача
    активная выдача другому?           → 409 copy_taken + текущая выдача
    INSERT loans                       ← loans_one_active_per_copy
    INSERT events (issue)
  COMMIT
```

Возврат в той же транзакции: если `returned_at` уже есть — ответ с текущим состоянием, события нет. Поэтому повтор из второй вкладки или после потерянного ответа не меняет время закрытия.

## Время

Все моменты — UTC в ISO 8601. Интерфейс переводит «Вернуть до» из местного времени в UTC (`localToIso`), фильтр истории «по дату» берёт начало следующего местного дня. Сервер без часового пояса не принимает (400): иначе срок зависел бы от пояса контейнера.

## Решения и причины

| Решение | Причина |
|---|---|
| Частичный уникальный индекс | вторая параллельная выдача невозможна даже в обход проверки в коде |
| Просрочка при чтении | не нужен фоновый процесс, граница срока точная |
| Сотрудники без учётных записей | ключи берут люди, которые журналом не пользуются |
| Список ключей по 50 | на 2 000 ключей полный список с экземплярами рисовал 2 000 карточек, ввод в поиск отвечал за 1,3 с |
| CSV с «;» и BOM, защита от формул | открывается в Excel с русской локалью, имена из журнала не исполняются как формулы |
