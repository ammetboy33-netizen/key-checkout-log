## Как повторить проверки

```bash
docker compose up -d --build                      # http://127.0.0.1:8219, дождаться healthy
python3 scripts/container_check.py --restart      # просрочка, 8 параллельных выдач, повторный возврат, CSV, роли, перезапуск

cd backend && python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
python -m pytest                                  # 14 тестов

cd ../frontend && npm ci
npm test                                          # 3 теста Vitest
npm run build
npm run e2e:install && npm run e2e                # 17 сквозных тестов против контейнера (+1 замер, пропускается без синтетики)
docker compose exec app python -m app.synthetic 2000 10 && npx playwright test e2e/perf.spec.ts
npm run e2e:local                                 # те же тесты без Docker (uvicorn из backend/.venv на :8319)
```

**Особенность окружения.** Песочница перехватывает исходящий TLS прокси с собственным корневым сертификатом, поэтому `docker compose up -d --build` здесь падает на `pip install` с `certificate verify failed`. Образ собирался так: `docker build --secret id=extra_ca,src=<ca-bundle> -t key-checkout-log:local . && docker compose up -d`. Это путь README для корпоративного прокси. Обычная `docker compose up -d --build` в этой песочнице не проверена.

## Раунд 1. Правила и полнота продукта

Сверка с ТЗ: записи ключей с условной меткой и номером экземпляра; журнал хранит сотрудника, время выдачи и возврата; одна активная выдача на экземпляр (индекс); операции доступны дежурному, регистрация — администратору; демо с вымышленными помещениями; выдача со сроком; просрочка на чтении; повторный возврат оставляет исходное время закрытия; контракты `GET /keys`, `POST /key-loans`, `POST /key-loans/{id}/return`, `GET /key-loans?status=overdue`; поиск и экспорт журнала.

| Проверка или решение | Результат |
|---|---|
| Точная граница срока | строго позже срока — просрочка: тест с подменой `now()` на момент срока и на секунду позже, тот же критерий в SQL (`due_at < now`) и в интерфейсе |
| Срок без часового пояса | 400 с указанием поля: иначе срок зависел бы от пояса контейнера |
| Выдача со сроком в прошлом | разрешена (нужна по ТЗ для проверки), интерфейс предупреждает «Срок уже прошёл: выдача сразу попадёт в просроченные» |
| Два экземпляра одного ключа | выдаются независимо, ключ «нет доступных», когда оба на руках |

Дефектов продукта в этом раунде не нашёл: тесты API прошли с первого запуска. Это говорит о покрытии тестов, а не гарантирует отсутствие ошибок.

## Известные ограничения

- Обычная `docker compose up -d --build` без прокси в этой песочнице не проверялась.
- Нет брони, подписи при получении и уведомлений о просрочке.
- Сквозные тесты сбрасывают демо через `/api/demo/reset`: на базе с настоящими данными их запускать нельзя.
- Один экземпляр сервера: SQLite не рассчитан на несколько реплик.
