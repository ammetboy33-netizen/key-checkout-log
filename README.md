# 219 · Журнал выдачи ключей

`key-checkout-log` — веб-приложение с сервером. Администратор регистрирует физические ключи и их экземпляры, дежурный выдаёт экземпляр сотруднику со сроком возврата и принимает возврат. Видны доступные ключи, ожидаемые возвраты и просрочки, история фильтруется по ключу, дате и типу операции и выгружается в CSV. Один экземпляр нельзя выдать двоим: это гарантирует уникальный индекс в базе.

Стек: React + TypeScript + Vite (интерфейс), FastAPI + SQLite (сервер). Всё упаковано в один Docker-контейнер с одним портом.

## Первый запуск (Docker)

Требования: Docker с Compose v2.

```bash
docker compose up -d --build
```

Откройте **http://127.0.0.1:8219**. Порт опубликован только на `127.0.0.1`, поэтому журнал доступен лишь с этого компьютера. При первом старте применяются миграции и создаются демоданные. Готовность — `curl http://127.0.0.1:8219/api/health` → `{"status":"ok",…}`, контейнер становится `healthy`.

| Роль | Логин | Пароль |
|---|---|---|
| Администратор (Ольга Ветрова): ключи, экземпляры, сотрудники, выдача и возврат | `admin` | `admin-demo` |
| Дежурные (Сергей Ким, Нина Ли): выдача, возврат, просрочки, история | `duty`, `duty2` | `duty-demo` |

На экране входа есть кнопки демо-входа (только при `DEMO_MODE=1`).

Демоданные: 6 ключей на 10 экземпляров (`К-101`…`К-302`, помещения вымышлены), 6 сотрудников, три выдачи в прошлом и три активные. `К-102 №1` у Глеба Наумова просрочен со вчерашнего дня.

```bash
docker compose exec app python -m app.seed                 # создать, если нет (повторный запуск не дублирует)
docker compose exec app python -m app.seed --reset         # вернуть демо к исходному виду
docker compose exec app python -m app.synthetic 2000 10    # 2 000 ключей и 40 000 выдач в истории для замеров
```

Данные хранятся в томе `keys-data` (`/data/key-log.sqlite3`) и переживают `docker compose restart` и `docker compose down` + `up`. Полный сброс — `docker compose down -v`.

Если сборка идёт через корпоративный прокси с собственным корневым сертификатом (ошибка `certificate verify failed` на `npm ci` или `pip install`), передайте сертификат необязательным секретом сборки:

```bash
docker build --secret id=extra_ca,src=/path/to/ca.pem -t key-checkout-log:local .
docker compose up -d
```

## Демонстрационный сценарий (по ТЗ)

1. Войдите как **Сергей Ким** (дежурный). У ключа `К-202 Кабинет 7` нажмите «Выдать», выберите «Анна Белова», в поле «Вернуть до» поставьте время на полчаса раньше текущего. Появится «Срок уже прошёл: выдача сразу попадёт в просроченные». «Выдать К-202 №1».
2. «Просрочки»: `К-202 №1` у Анны Беловой «просрочен на 30 мин» и демо-просрочка `К-102 №1`.
3. Повторная выдача того же экземпляра заблокирована. В окне второго дежурного (`duty2`), открытом раньше, «Выдать» отвечает «К-202 №1 уже выдан: Анна Белова…» и обновляет карточку. Сервер отвечает 409 и на прямой запрос.
4. «Принять возврат» — экземпляр снова «свободен», во «Выдано» его нет. Повторное «Принять возврат» из другой вкладки отвечает «уже был возвращён»: время закрытия не меняется, второй записи нет.
5. «История» → ключ `К-202`: создание, экземпляр, выдача, возврат. Фильтр «Операция: возврат» оставляет одну запись. «Скачать CSV» выгружает журнал с теми же фильтрами (разделитель «;», открывается в Excel).

## Проверки

```bash
# Сервер: pytest (API, роли, точная граница срока, параллельные выдачи на настоящем uvicorn, перезапуск)
cd backend
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
python -m pytest

# Интерфейс: Vitest, сборка, сквозные тесты Playwright против запущенного контейнера
cd ../frontend
npm ci
npm test
npm run build
npm run e2e:install              # один раз: Chromium
npm run e2e                      # против http://127.0.0.1:8219 (docker compose up -d)
# замер: docker compose exec app python -m app.synthetic 2000 10 && npx playwright test e2e/perf.spec.ts

# Контейнер целиком: просрочка, 8 параллельных выдач, повторный возврат, CSV, роли, перезапуск
cd ..
python3 scripts/container_check.py --restart
```

Сквозные тесты и `container_check.py` сбрасывают демо через `/api/demo/reset`: этот вызов удаляет все ключи, сотрудников, выдачи и журнал и создаёт демо заново. Не запускайте их на базе с настоящими данными.

## Запуск без Docker (разработка)

```bash
cd backend && . .venv/bin/activate
DEMO_MODE=1 SEED_DEMO=1 uvicorn app.main:app --port 8000 --reload     # API на :8000, база ./data/key-log.sqlite3
cd ../frontend && npm run dev                                           # http://localhost:5219, /api проксируется на :8000
```

Собранный интерфейс без Vite: `npm run build`, затем запуск сервера с `STATIC_DIR=../frontend/dist` → http://127.0.0.1:8000. Сквозные тесты без Docker: `npm run e2e:local` (uvicorn на :8319 с временной базой, нужен собранный `dist/`).

## Учётные записи

Демо-пользователи создаются сидом. Свои — командой (пароль спрашивается скрыто):

```bash
docker compose exec -it app python -m app.users add petrov --role duty --name "Иван Петров"
docker compose exec -it app python -m app.users add boss --role admin --name "Мария Иванова"
docker compose exec -it app python -m app.users passwd petrov
```

Сотрудников, которым выдают ключи, добавляет администратор во вкладке «Сотрудники»: учётные записи им не нужны.

## Переменные окружения

См. `.env.example`: `APP_PORT` (по умолчанию 8219), `DEMO_MODE`, `SEED_DEMO`, `COOKIE_SECURE`. Внутри контейнера — `DB_PATH=/data/key-log.sqlite3`, `STATIC_DIR=/app/static`. Секретов нет: сессии — случайные токены в базе, пароли хранятся как PBKDF2-SHA256.

## Где что лежит

| Путь | Назначение |
|---|---|
| `backend/app/main.py` | маршруты API, роли, CSV |
| `backend/app/service.py` | правила: каталог, экземпляры, выдача и возврат в транзакции, просрочка при чтении, история, экспорт |
| `backend/app/web.py`, `auth.py`, `users.py` | вход, сессии, роли, консоль учётных записей |
| `backend/app/db.py`, `backend/app/migrations/` | SQLite, транзакции `BEGIN IMMEDIATE`, миграции |
| `backend/app/seed.py`, `backend/app/synthetic.py` | демоданные и синтетика |
| `backend/tests/` | pytest |
| `frontend/src/` | интерфейс: ключи, выдано, просрочки, история, сотрудники |
| `frontend/e2e/` | Playwright |
| `scripts/container_check.py` | проверка запущенного контейнера |
| `Dockerfile`, `compose.yaml`, `.env.example` | контейнер и запуск |
| `docs/` | карточка, архитектура, приёмка, ассеты, исходное ТЗ |
